# 发布过程

首版建议公开源码配方和验证方法。二进制 Release 是单独步骤，当前仓库没有自动发布或刷机工作流。

1. 冻结 `sources.lock.json`、配置、补丁、默认文件和工具，赋予明确的新版本。保留上游引用和每个文件原有许可。
2. 执行仓库检查，对最终 Git 暂存内容及历史做独立的 secrets 扫描和人工复核。检查个人地址、域名、MAC、设备 ID、节点、订阅、凭据、压缩包和证书；`.gitignore` 不是完整的隐私检查。
3. 在全新工作目录，仅使用公共源和可选公开源码缓存构建。记录依赖和主机构建环境；通过配置与镜像检查。
4. 对将发布的实际镜像做实机验收，准确区分历史基线、当前静态检查与当前运行测试。
5. 核对实际软件包许可，提供与二进制对应的完整源码、修改、配置及必要构建材料。上游链接和差异补丁不能独自替代适用许可证要求的对应源码。把所需源码归档与发布记录一起保留，并检查其自身不混入私人文件。
6. 固件、包、对应源码归档、包清单与 SHA256 放 Releases；源码 Git 历史不存大镜像、缓存或日志。可增加发布签名及验证说明。
7. README/Release 明确支持的板型、已验证引导/分区方式、功能裁剪、已知边界和恢复方法。不要把 factory 镜像存在理解为原厂直刷已验证。

此仓库的许可证适用于项目新增内容。第三方组件仍按自身许可证分发；发布者需根据实际产物完成许可核对。

# 验证范围

## 本公开仓库

这是从已测试的内部配方整理出的源码开发版。公开版更改了默认配置标记和命名，合并了 WAN DNS 保护，去除了私人部署依赖，新增了公开取源入口。这些变化意味着公开版不是内部镜像的逐字节副本。

实际完成的仓库检查写在 [VALIDATION-RESULTS.json](VALIDATION-RESULTS.json)。未执行的阶段必须保持 `false` 或 `pending`，不能用内部基线结果代填。本仓库的静态镜像检查器也明确输出 `runtime_tested: false`。

## 历史内部基线证据

以下是同一硬件、相同锁定源版本与核心裁剪方案的既往结果，用于解释设计依据，不是公开版镜像验收证书：

- 板型/镜像/组件检查，VLESS 和真实外部 Hysteria2，普通 MTU 的代理 UDP。
- 七个模拟来源、HTTPS 反代、SOCKS、TCP/UDP DNAT、WebSocket/SSE、文件数据校验。
- Tailscale 双向访问、新身份持久化、软件重启和实际断电冷启动恢复。
- 两种代理协议各 30 分钟，合计 60 分钟混合测试通过；最低可用内存约 46 / 56 MiB，无 OOM、异常重启或持续交换写出。
- 早先串联测试路径曾出现公网 TLS 超时，原因未完全证明；后续隔离路径未复现，不能抹去原失败。
- 超大 UDP 回包存在边界，独立参考也有相同表现；不宣称所有尺寸 UDP 均通过。
- 历史测试的 LAN 链路只有 100 Mbps，真实千兆性能未验收。机房真实后端、证书自动续期与长期生产运行仍需另外验证。

## 发布候选镜像建议验收

确认板型与实际升级/恢复路径；检查 DHCP/DNS、WAN 边界和内网地址；用真实 VLESS/Hysteria2 节点验证 TCP/UDP 与分流；验证真实 HTTPS 后端、Tailscale 直连或中继路径；检查代理故障不会阻断独立管理；执行软件重启、冷启动与至少 24 小时有业务采样的观察。记录来源、时间、负载、最低可用内存、交换活动、丢包和失败，不把“经过了一天”当作覆盖一天的有效观测。

不要在唯一远程管理路径上运行断网、重启或刷机测试。硬件测试需要使用者明确建立安全拓扑，本仓库不会自动管理电脑网卡或替换默认路由。
